# Контракт WebSocket для фронта (React + Redux)

## Подключение

- URL: `http://localhost:4000` (или значение `PORT`)
- Соединение устанавливается **один раз после логина** пользователя и закрывается
  при разлогине. Переподключаться при переключении чата **не нужно**.
- `chatId` **больше не передаётся в query**. Подключение без параметров:

  ```js
  const socket = io("http://localhost:4000");
  ```

- Чтобы получить историю конкретного чата (при открытии/переключении), клиент
  отправляет событие `history:get` (см. ниже), а не переподключается.

## Исходящие события (клиент -> сервер)

- `history:get` -> `{ chatId }`
  - запросить историю чата; сервер ответит событием `history`.
  - отправлять при открытии чата и при переключении между чатами.
- `chat:join` -> `{ chatId, userName }`
  - присоединиться к чату (учёт участников). Сервер запоминает `userName` на
    соединении, чтобы корректно убрать его при `disconnect`.
- `chat:leave` -> `{ chatId, userName }`
  - покинуть чат (учёт участников).
- `message:send` -> `{ chatId, userName, content }`
  - отправить сообщение в чат.
- `typing` -> `{ chatId, userName, isTyping }`
  - сигнал «пользователь печатает / перестал печатать». Транслируется остальным
    участникам.

## Входящие события (сервер -> клиент)

- `history` -> `{ type: "history", messages: Message[] }`
  - ответ на `history:get`; диспатчить в Redux как «загрузить историю чата».
- `message:new` -> `{ type: "message", message: Message }`
  - новое сообщение. Рассылается **всем подключённым клиентам по всем чатам**
    (broadcast). Клиент сам раскладывает по `message.chatId` и диспатчит
    «добавить сообщение».
- `typing` -> `{ type: "typing", chatId, userName, isTyping }`
  - кто-то печатает. Приходит **всем кроме самого отправителя**. Клиент решает,
    показывать ли индикатор, по `chatId`.
- `chat:created` -> `{ type: "chat:created", chat: Chat }`
  - отправляется REST-роутом при `POST /chat`, чтобы обновить список чатов без
    перезагрузки.

## Ошибки

- `error` -> `{ message: string }`
